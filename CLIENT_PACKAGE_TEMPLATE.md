# Client package template (what every paid zip should include)

Used by Olivia Steele technical delivery team. Public so buyers know what “done” looks like.

## Package contents

| Path | Purpose |
|------|---------|
| `README.md` | What this tool does / does not do |
| `RUNBOOK.md` | Exact commands to run on the client PC |
| `ACCEPTANCE.md` | Checklist to sign off delivery |
| `samples/` | Redacted or synthetic before/after |
| `src` or `*.py` | The tool itself |
| Optional `LICENSE` | Client keep rights for the package |

## Engagement steps

1. Redacted samples from client  
2. Written done-means + price  
3. Proof run on samples  
4. Zip handoff  
5. Short defect-fix window for package bugs (not unlimited free feature work)

## Never in a client zip

- Private house paths (JoeysAI full tree)  
- API keys, vault files, personal health/family data  
- Unscoped “whole system” installs  

## Doctrine

dig ≠ proof on research; for client work, acceptance checklist is the truth.
